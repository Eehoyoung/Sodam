# 소담 (Sodam) — 제품 요구사항 문서 (PRD)

> 이 문서는 소담의 **단일 제품 사양 원본**이다. 기능을 추가·변경하기 전에 해당 도메인 섹션을 먼저 읽는다.
> 구현 관행·명령어는 `CLAUDE.md`, 코딩 규칙은 `.claude/rules/`, 보안 점검은 `.claude/skills/security-review/` 참조.

---

## 1. 제품 개요

### 1.1 한 줄 정의

노무 지식이 없어도 근로기준법 위험을 놓치지 않도록, 출퇴근·급여·계약을 한 앱에서 관리하고 위험 신호를
**사전에** 알려주는 매장 인력관리 서비스.

> 2026-08-15 포지셔닝 전환(계획서 `docs/260815/260815_소담_포지셔닝전환_계획서.md`) — 기존 정의("출퇴근
> 기록부터 급여 명세서 발급까지 한 앱에서 끝내는")는 무료 경쟁 서비스가 이미 동등하게 제공한다. 소담이
> 다른 지점은 §4.7 노무 안전장치(사전 예측)와 §4.14 개인 모드 데이터 자산화다.

### 1.2 해결하는 문제

- 소상공인은 수기 출퇴근부·엑셀 급여계산으로 인해 **급여 오류·노동법 위반 리스크**에 상시 노출된다
- 기존 경쟁 서비스(뉴플로이 기본 29,700원+인당 과금, 시프티, 무료인 보스몬 등)는 소규모 매장에 과하거나
  비싸거나, 무료여도 **법 위반 위험을 사전에 짚어주는 깊이까지는 들어오지 않는다**(채용 광고가 주 수익원인
  서비스는 "채용을 줄이는" 경고 기능과 구조적으로 이해충돌이 있다)
- 노동법 경고 대부분은 위반이 **이미 벌어진 뒤에야** 나타난다 — 소담은 확정된 스케줄만으로 위반 가능성을
  미리 계산해 **사고가 나기 전에 조정할 기회**를 준다("틀린 뒤에 아는 것"이 아니라 "틀리기 전에 아는 것")
- 직원 입장에서는 자신의 근무기록·급여 내역을 투명하게 볼 수단이 없다

### 1.3 타깃

- **주 타깃(구매자)**: 직원 1~10명 규모 매장의 사장. 노무 지식이 거의 없음
- **부 타깃(사용자)**: 해당 매장의 아르바이트/직원. 상당수 미성년자 포함 가능(미성년 보호 장치 필요)

### 1.4 플랫폼

- 모바일 앱: React Native (Android/iOS, iOS Sign in with Apple 지원)
- 백엔드: Spring Boot API 서버 (포트 7070) + MySQL + Redis

## 2. 역할과 페르소나

| 역할 | 설명 | 진입 흐름 |
|---|---|---|
| **사장 (Master)** | 매장 소유자. 매장 등록·직원 관리·스케줄 확정·급여 정산·구독 결제의 주체 | 회원가입 → 사장 선택 → 매장 등록 |
| **직원 (Employee)** | 매장 소속 근로자. 출퇴근 기록, 본인 스케줄·급여 열람, 교대 요청 | 회원가입 → 직원 선택 → 초대코드로 매장 입사 |
| **매니저 (Manager)** | 사장이 매장 소속 직원에게 매장별 권한을 위임한 운영 역할. 별도 전역 계정 역할이 아니며 위임 범위 안에서만 업무 수행 | 직원 입사 → 사장이 권한 선택·위임 → 매니저 마이페이지 |

- 한 사용자는 여러 매장의 사장이면서 동시에 다른 매장의 직원일 수 있다 (역할은 매장-사용자 관계 단위)
- 인증: 이메일/비밀번호, 카카오 OAuth, iOS Sign in with Apple + JWT (액세스 1시간 / 리프레시 7일)

### 2.1 개인 모드 — 역할이 아니라 "상태"

**개인 모드(Personal Mode)** 는 위 3역할과 같은 층위의 네 번째 역할이 **아니다.** 매장에 소속되지 않은
사용자가 혼자서도 근무 기록을 남길 수 있도록 켜는 **직교(orthogonal) 상태**다. 상세 사양은 §4.14.

| | 개인 모드 OFF | 개인 모드 ON |
|---|---|---|
| **매장 소속 있음** | 일반 직원 (기본) | 겸업 — 매장 근무 + 개인 근무를 함께 기록 |
| **매장 소속 없음** | 유휴 계정 (이탈 위험 구간) | 홀로 일하는 사람 — 개인 근무지·기록·연간 집계 사용 |

- 개인 모드를 켜도 **계정 역할(`UserGrade`)은 바뀌지 않는다.** 등급을 낮추면 인증채용·채팅·경력증명서가
  전부 차단되어(§4.12 자격 기준과 충돌) 데이터 연속성이 깨지기 때문이다
- 따라서 개인 모드 사용자는 **인증채용 자격을 그대로 유지**한다 — 소담으로 출퇴근을 찍은 이력이 있으면
  재직 여부와 무관하게 구직 시장에 노출될 수 있다
- ⚠️ 사용자 노출 문구는 "개인 모드"·"나 홀로 근무 기록" 등을 쓴다. **"개인사용자"는 사용하지 않는다** —
  근로기준법 §2①2의 "사용자"(=사업주)와 충돌해 이용자가 스스로를 근로자가 아닌 것으로 오인할 소지가 있다
  (2026-08-07 노무 검토). 내부 식별자(`UserGrade.Personal`, `personal/` 패키지)는 유지

## 3. 핵심 사용자 여정 (퍼널)

```
[사장]  가입 → 매장 등록(주소 검색·GPS 반경 설정) → 초대코드 발급
   ↓
[직원]  가입 → 초대코드 입력 → 매장 입사 → 근로계약·동의
   ↓
[일상]  직원 출퇴근(GPS/NFC/사장승인) ↔ 사장 실시간 현황 확인
   ↓
[주간]  사장 스케줄 작성(드래그앤드롭 보드) → 확정 → 직원 알림
   ↓
[월간]  정산주기 도래 → 정산 마법사(3단계) → 급여 확정 → 명세서 PDF 발급
   ↓
[성장]  직원 증가 → FREE 상한(2명) 도달 → 페이월 → 유료 전환

[채용]  인증 직원 구직 ON ↔ 사장 구직자 탐색·채용 제안
        사장 구인공고 게시 ↔ 직원 주변 공고 지원 → 수락 후 초대코드 공개
```

### 3.1 개인 모드 퍼널 (매장 퍼널의 앞뒤를 잇는 경로)

개인 모드는 매장 퍼널의 **바깥이 아니라 앞뒤**에 붙는다. 매장에 들어오기 전과 나간 뒤를 잇는 구간이다.

```
[진입 A · 신규]   가입 → 목적 선택에서 "혼자 일해요" → 개인 모드 ON
[진입 B · 퇴사]   매장 소속 0건이 7일 지속 → 다음 로그인에 전환 권유 → 동의 → 개인 모드 ON
   ↓
[일상]  개인 근무지 등록(이름·주소·시급) → 스스로 출퇴근 기록 → 월별 집계
   ↓
[연간]  연간 근무·소득 합산 → 3.3% 원천징수 환급 신호 안내(홈택스 위임)
   ↓
[복귀]  인증채용으로 새 매장 매칭 → 초대코드 → 매장 입사 → 매장 퍼널 합류
        (개인 모드는 끄지 않아도 된다 — 겸업 상태로 공존)
```

- **B 경로가 이 기능의 존재 이유**다. 지금은 퇴사하면 소담에서 할 일이 없어져 이탈하는데,
  그 사용자야말로 §4.12의 "소담으로 출퇴근을 찍어본 인증된 구직자"다
- 개인 모드는 종착지가 아니라 **다음 매장으로 가는 대기실**로 설계한다

## 4. 기능 요구사항 (도메인별)

FE 도메인 폴더(`frontend/src/features/`)와 1:1 대응. 구현 상태: ✅ 완료 / 🔶 부분 / ⛔ 인간 결정 대기.

### 4.1 인증·온보딩 (`auth`, `onboarding`, `welcome`) ✅

- 이메일 가입/로그인, 역할 선택(사장/직원), 프로필 기본정보 입력
- 카카오 OAuth 로그인, iOS Sign in with Apple. Apple identity token의 서명·issuer·audience를 서버에서 검증하고 `sub`를 재로그인 식별자로 사용하며, 이메일이 같은 기존 계정에는 Apple 식별자를 연결
- 약관 동의 + **위치정보 수집 동의**(별도 동의, PIPA) 이력 저장 (V7)
- JWT 만료 시 FE가 401 응답을 받아 리프레시 토큰으로 자동 갱신 — **BE는 만료 토큰에 반드시 401을 반환** (403이면 갱신 루프가 죽는다, 이력: 커밋 322e9a0)
- 신규 직원 랜딩에 "매장 입사" CTA 노출 🔶 (JoinStoreByCode 기능은 동작하나 진입점이 묻혀 있음)

### 4.2 매장 (`store`, `workplace`) ✅

- 매장 등록: 상호·업종·주소(카카오 주소검색 → 좌표 지오코딩)·**출퇴근 인정 반경(GPS)** 설정
- 초대코드 발급/재발급, 직원 목록·상세, 매장 수정
- 매장별 NFC 태그 등록·조회·비활성화·재활성화
- 매장 수는 플랜 게이팅: FREE/STARTER 1개, PRO+ 멀티매장 (§4.8)
- 운영시간 도메인은 **야간(자정 교차)을 의도적으로 지원하지 않음** — 출퇴근 인정 윈도우 리스크 때문. 변경하려면 인간 결정 필요
- ⛔ `workplace` 화면(WorkplaceList/Detail)은 네비게이션 미배선 상태 — 재배선/제거는 인간 결정 대기

### 4.3 직원 관리·계약 (`info`, `wage`, `contract`, `electronicSignature`, `document`, `certificate`) ✅

- 직원별 시급/월급 설정, 수습 여부, 노무 정보(4대보험 가입 구분)
- 근로계약서 작성·보관과 외부 전자서명 요청. 서명 봉투 상태 조회·갱신, 완료 문서·완료 인증서 다운로드, 무결성 검증 지원
- 임금·고용형태 변경은 즉시 덮어쓰지 않고 근로조건 변경안(DRAFT → SIGNING → VERIFIED → APPLIED)을 생성해 전자서명 완료 및 효력 발생일 도래 후 적용
- 미성년 직원 보호(`minorguard`): 친권자 동의서, 야간·연장근로 제한 경고

### 4.4 출퇴근 (`attendance`, `breakrecord`) ✅

세 가지 기록 방식(매장 설정으로 선택):

1. **GPS**: 매장 좌표 반경 내에서만 출퇴근 버튼 활성화. 좌표는 검증에만 쓰고 **로그에 남기지 않는다** (P0 수정 완료)
2. **NFC**: 사장이 등록·활성화한 매장 태그를 직원이 태깅하면 서버가 매장-태그 매핑을 검증해 출퇴근 처리. 네트워크 지연 시 제한된 범위 안에서 오프라인 큐 적재 시각을 보존하고 범위를 벗어나면 서버 시각 사용
3. **사장 승인**: 위치·NFC 없이 직원이 요청 → 사장에게 실시간 알림 → 승인 시 **요청 시각**으로 기록(위치 null), 거절 흐름 포함 (V25)

- **iOS 1차 출시 범위**: NFC 출퇴근은 iOS에서 제외(GPS·사장승인 방식만 노출) — CoreNFC 제약·검증 비용 대비 효용 낮음(결정 근거: `docs/260718/iOS_마스터_출시_계획서.md`). Android NFC 경로는 유지. iOS 화면(`AttendanceScreen`/`AttendanceSummaryPanel`)은 NFC 옵션을 표시하지 않는다
- 휴게시간 기록(`breakrecord`), 근무 타이머는 서버 기준 시각으로 표시(기기 타임존 의존 금지)
- 퇴근 후 상태는 `checkOutTime` 원본 필드로 판정 — 캐시된 "근무중" boolean 금지 (이력: 커밋 02e57d0)
- 사장 화면에 출퇴근 현황 실시간 반영 (WebSocket, §4.9)

### 4.5 스케줄 (`shift`, `timeoff`) ✅

- 주간 스케줄 보드: **드래그앤드롭**으로 시프트 배치 (고정 행높이 결정적 레이아웃)
- 야간 시프트: 종료 ≤ 시작이면 익일 종료로 해석, `shiftDate`는 시작일 기준
- 시프트 템플릿 저장/적용, 시프트 수정(PUT, 수정 시 확정 상태 리셋)
- **스케줄 확정** → 소속 직원 전원에게 알림 발송
- 교대 요청(shift swap, V31): 직원 간 근무 교환 요청·승인
- 연차/휴무 신청(`timeoff`)

### 4.6 급여 (`salary`, `bonus`) — 코어는 `backend/core/payroll/` ✅

- **정산주기(PayrollCycle)**: 매장별 설정 — 시작(전월/당월 N일), 마감(당월/익월 N일 또는 말일), 지급일. `@Embedded`, V26
- **계산 요소**: 기본급(시급×근무시간), 주휴수당(주 15시간 이상), 야간수당, 연장수당, 휴일근로 가산(V8), 4대보험 공제(`SocialInsuranceRates` — 요율 연도 명시), 소득세, 항목별 공제(V6), 퇴직금(STARTER+)
- **정산 마법사**: 3단계 UI(대상 확인 → 계산 검토 → 확정) → **급여 명세서 PDF** 발급(OpenPDF, STARTER+ 게이팅)
- **즉시 보너스**: 사장이 직원에게 수시 보너스 지급 기록
- 급여 데이터 접근은 **본인 것 + 해당 매장 사장만** (급여 RBAC — P0 수정 완료)
- 권한을 받은 매니저는 급여 조회·확정 업무를 수행할 수 있다. 급여 확정·지급·발급은 비밀번호 재인증(step-up), 현재 위임 권한 재검증, 행위자 감사 기록을 필수로 한다
- 🔶 급여 계산 ↔ 정산주기 연동은 미완 (주기 설정은 저장되나 계산에 완전 반영 전)

### 4.7 노무 안전장치 (`minorguard`, `risk`, `evidence`) 🔶

- 노동법 경고: 최저임금 미달, 주 52시간 초과, 휴게 미부여 등 감지 시 사장에게 경고 (STARTER 기본 / PRO 풀)
- 근로감독 대비 증거 패키지(`evidence`): 출퇴근·계약·명세서 이력 묶음 내보내기 (PREMIUM)
- 법적 판단이 필요한 문구·기준은 노무사 검토 후 확정 (⛔ 인간)

### 4.8 수익화 (`subscription`, `purchase`, `referral`) ✅ (결제 live 키만 ⛔)

### 4.11 매니저 위임 (`manager`) ✅ (대리 계약 체결은 기능 플래그)

- 사장은 매장 소속 활성 직원에게 매니저 권한을 부여하고 권한 변경·해제·목록 조회·위임 감사 이력 조회를 수행한다
- 기본 권한: 출퇴근 승인, 스케줄 관리, 휴무 승인, 직원 조회, 대타·공지 관리, 대시보드 조회
- 선택 권한: 채용 관리, 급여 조회·확정, 임금 수정, 직원 비활성화, 계약 관리, 매장 수정
- 매니저는 `내 관리 매장`에서 위임받은 매장과 권한을 확인하며, 서버는 각 API에서 `StoreAccessGuard`와 세부 권한을 함께 검증한다
- 급여 확정·발급 등 고위험 업무는 비밀번호 재인증과 위임 버전 재검증 후 사장/매니저 행위자를 구분해 감사 기록을 남긴다
- 매니저의 대리 근로계약 체결은 법무 승인용 기능 플래그가 기본 비활성 상태이며, 플래그 활성화 후에도 발급 당시 위임 근거와 현재 권한을 최종 확정 직전에 다시 검증한다

### 4.12 인증채용(구직·구인) (`recruitment`) ✅ (v1 무과금)

소담으로 출퇴근을 찍어본 직원만 구직 시장에 노출되는 "인증된" 채용 매칭. 상세 계획: `docs/260711/260711_작업통합.md` Part 2.

- **자격(인증) 기준**: 소담에 존재하는 매장에서 소담으로 출퇴근을 찍은 적이 있는가(`attendance` 기록 존재 여부) — 재직 여부와 무관, 퇴사자도 과거 이력만 있으면 가능
- **지역 매칭**: 희망지역 정확히 2개 필수(주소검색 → 지오코딩 → 저장 시 좌표 영속화), 매장 좌표와 Haversine 거리 4km 이내만 노출
- **구직 유형**: 당일 대타(SUBSTITUTE) / 정기(REGULAR), 복수 선택 가능 — 사장 리스트 필터·채용 제안 매칭의 분기점
- **근무 가능 시간**: 요일별로 다르게 설정(예: 월 10~18시, 토 18~22시), 구직 ON 전환 시 1개 요일 이상 필수. v1은 야간(종료≤시작) 미지원
- **업종 분류**: 12종 중 최대 3개 선택(구직 ON 시 1개 이상 필수) — 매장 업종과 일치 시 "업종 일치" 강조
- **구직 OFF 시** 희망지역·근무가능 데이터는 유지되며 재 ON 시 그대로 복구
- **경력 표시**: 사장 리스트·구직자 상세에 현재 소속만 노출(이름·나이·경력·근무가능·희망지역·거리). 활성 재직 없으면 "휴직중"
- **사장의 채용 제안**: 필터링한 구직자에게 당일 대타/정기 제안을 발송. 중복 대기 제안을 차단하고 직원이 수락·거절하며, 수락 시에만 초대코드 공개
- **직원의 매장 지원**: 사장이 올리는 구인 공고(매장당 1건, 공개/마감 전환) 기반 지원 — 주변 공고는 희망지역 반경과 유형·업종으로 필터링하며, 사장이 수락·거절하고 수락 시에만 초대코드 공개
- **응답 상태**: 제안과 지원은 PENDING / ACCEPTED / DECLINED / EXPIRED 상태를 사용하며 만료 상태는 조회 시점에 반영
- **진입점**: 양 역할 모두 메인 스크린 빠른 메뉴가 유일 진입점(직원: `EmployeeAttendanceHome`, 사장: `OwnerDashboardScreen`)
- **과금**: v1은 무과금 개방 — 기능 완성 후 별도 단계로 도입 예정(제안 발송 지점에 훅만 확보)
- **PII 최소화**: phone·email·생년월일 원본은 리스트/상세 응답에 포함하지 않는다(나이만 파생 노출). 희망지역 주소·좌표는 매장 주소와 동급 민감도로 PII 암호화 컨버터 미적용 — 단 로그에 좌표·주소 원문 출력 금지
- 구현 상태: 프로필·구직자 탐색·채용 제안·구인공고·주변 공고·지원 왕복 및 역할별 채용함 UI/API 구현 완료. 과금 도입은 별도 단계

### 4.13 매입장부 (`features/purchase/`, F-BUY-01) ✅

영수증 기반 경량 매입 기록(사장 전용). ⚠️ §4.8의 `purchase` 태그(구독/과금)와 이름만 같을 뿐 무관한 기능 — 실제 코드 위치는 FE `frontend/src/features/purchase/`, BE `PurchaseController`/`PurchaseService`/`Purchase`·`PurchaseItem` 엔티티다.

- **스코프 경계(IDENTITY §8 개정, 2026-06-16)**: "사는 것(매입)의 기록·비교"까지만. 재고 수량 자동차감·원가율·메뉴마진·POS 판매연동은 영구 Non-Goal — 확장 제안 시에도 이 경계를 넘지 않는다
- **플로우**: 매장 상세 화면 "매입장부" 메뉴 진입 → 영수증 촬영(OCR 초안, 현재 Noop 기본빈) 또는 직접 입력 → 확인·보정 후 저장 → 목록·가격비교·발주참고 3갈래로 재소비
- **분류**: 야채·청과/육류/수산/주류/음료/소모품/기타 7종(`PurchaseCategory`)
- **가격비교**: 품목별 시점·거래처별 단가 추이 + 직전 대비 변동률 + 최저가 거래처
- **발주 참고**: 최근 N일 매입을 품목별로 묶어 매입주기·최근수량 산출 — 재고 차감 아님, 화면에 면책 문구 상시 노출
- **영수증 원본**: `ObjectStorage`(로컬 `uploads/`, 매장별 접두사)에 저장, 매장 소유 검증을 거친 인증 엔드포인트로만 조회(공개 정적 서빙 아님 — 거래처·금액이 담겨 공개 URL 부적합)
- **OCR**: `ReceiptOcrClient` 추상화 — `sodam.ocr.provider` 미설정 시 `NoopReceiptOcrClient`가 빈 초안 반환(외부 호출 0), 수기 입력으로 완전히 동작. CLOVA 실 클라이언트는 코드 완성 상태이나 활성화(운영 env 키 투입)는 외부 API 계약·비용이 걸린 인간 승인 사항
- **인가**: `@MasterOnly` + `StoreAuthorizationPolicy.assertMasterOwnsStore` — 전 엔드포인트 사장 전용
- **잔업(출시 이후)**: 부가세 매입자료 활용(`supplyAmount`/`vatAmount`) — 배선만 된 상태, 세무 정확성 검토 선행 필요(CLAUDE.md 명시)
- 상세 감사·계획: `docs/260803/260803_매입장부_갭수정_및_고도화_계획서.md`

### 4.14 개인 모드 (`personal/`, `UserGrade.Personal`) 🔶

매장에 소속되지 않은 사용자가 **혼자서 자기 근무를 기록**하는 모드. 역할이 아니라 상태다(§2.1).
BE `com.rich.sodam.personal` 패키지, FE `PersonalUserScreen`·`PersonalAnnualTaxScreen`.
전환 흐름·데이터 연속성의 실행 계획은 `docs/260807/260807_부가수익_및_무료기능_확장_계획서.md` WP-H.

**대상**: 매장에 소속되지 않은 근로자 — 단기·일용, 여러 곳을 옮겨 다니는 사람, 퇴사 직후 구직 중인 사람.
PRD 내부 용어는 **"무소속 근로자"** 를 쓴다. "프리랜서"·"1인사업자" 같은 사업소득자 함의 표현은
근로자성을 스스로 부정하게 만들 수 있어 제품 문구에서 사용하지 않는다.

**가치 제안**: ① 사장이 없어도 내 근무 기록이 남는다 ② 3.3% 떼인 돈을 돌려받을 수 있다는 걸 알려준다
③ 퇴사해도 소담을 떠날 이유가 없다(과거 기록 열람 + 인증채용 유지)

#### 기능 범위 (✅ 포함)

- **개인 근무지**: 사용자가 직접 등록(이름·주소·시급). 사장 승인 없음. 주소·시급은 PII 암호화 대상
- **개인 출퇴근**: 스스로 기록(자기신고). GPS·NFC·사장승인 방식은 **적용하지 않는다** — 검증 주체가 없다
- **집계**: 월별 근무시간·소득, 연간 근무지별 소득 합산
- **세금 신호**: 3.3% 원천징수 추정 + "5월 종합소득세 신고로 환급받을 수 있다"는 안내까지. 계산은 참고용
- **내 기록 열람**: 과거 매장 근무 이력(출퇴근·근로계약·명세서·인증채용)을 본인 스코프로 조회(§4.14 인가)

#### ⛔ Non-Goal (영구 제외 — 확장 제안에도 포함하지 않는다)

매입장부(§4.13)와 같은 방식으로 경계를 고정한다. 아래는 "아직 안 함"이 아니라 **하지 않기로 한 것**이다.

| 제외 항목 | 이유 |
|---|---|
| 개인 모드 기록 기반 **급여 계산·명세서 발급** | 급여는 사용자(사업주)가 확정하는 것. 자기신고 기록으로 급여를 확정하면 명세서의 신뢰가 무너진다 |
| 근로계약·전자서명·4대보험 | 상대방(사업주)이 있어야 성립. 개인 모드에는 계약 상대가 없다 |
| 개인 근무지에 **타인 초대·팀 관리** | 그 순간 그것은 매장이다. 매장 기능은 매장 도메인으로 가야 한다 |
| 홈택스·e-Tax 연계, 복식부기, 경비 처리 | 세무사법 — 소담은 집계·안내까지만. 신고·환급은 홈택스/정부24 위임 |
| 개인 모드 기록의 **증명서 발급** | 자기신고 기록은 제3자 확인이 없어 증명력이 없다. 증명서는 매장 기록(§4.3)에서만 |

#### 법규 준수 요건 (3자 교차검증 2026-08-07 반영, 누락 시 배포 불가)

- **동의 화면 필수 문구** — ① "임금·퇴직금·연차수당 등의 권리에 영향 없음" ② "근로관계 종료 여부·시기·

- **자기신고 라벨**: 개인 출퇴근 기록은 화면뿐 아니라 **내보낸 PDF 문서 자체에도**
  "본인 자기신고 기록이며 제3자(사업주) 확인이 없습니다" 표기
- **위장 자영업 방지**: 근무지 등록 화면에 "실제로 특정 업체의 지시·감독을 받으며 일하는 경우라면
  근로자성이 인정될 수 있습니다" 안내
- **연소근로자**: `MinorLaborGuardService`는 매장 스코프 전용이라 개인 모드에 미연결. 만 18세 미만이면
  최소한의 안내(야간근로 제한 등) 노출 검토
- **보관**: 3년(§4.14 데이터) — 3년 초과 보관·조회는 근로기준법 §42가 아니라 **정보주체 동의**를 근거로
  개인정보처리방침에 별도 항목으로 기재

#### 인가·데이터

- 과거 매장 기록 조회는 **매장 스코프가 아니라 본인 스코프**(`/api/me/history/**`, JWT userId로만 필터).
  요청에서 `storeId`를 받지 않아 구조적으로 BOLA가 불가능하다. **`StoreAccessGuard`는 수정하지 않는다**
- `personal_*` 테이블은 매장 도메인과 분리 유지. 두 기록을 물리적으로 합치지 않는다(증명력이 다르므로)
- 전환 트리거: 활성 `EmployeeStoreRelation` 0건이 **7일 이상 지속** 시 다음 로그인에 권유(즉시 푸시 금지 —
  퇴사는 민감한 시점이고, 부당해고 다툼 중(노동위 구제신청 3개월)일 수 있다)

## 5. 비기능 요구사항

### 5.1 보안 (상세: `.claude/rules/security.md`)

- 매장 스코프 API 전부 `StoreAccessGuard` 통과 (BOLA 차단 — 16건 수정 이력)
- PII(전화번호·사업자번호 등) AES-256-GCM 컬럼 암호화, 로그 마스킹, GPS 좌표 비로깅
- Rate limit(Bucket4j), 시크릿은 env 주입만

### 5.2 시간·지역

- 모든 시간 처리 기준 **Asia/Seoul**. 기기 타임존 의존 계산 금지
- 통화 KRW, 일(day) 표기 2자리 0패딩

### 5.3 성능

- 조회 캐시(ehcache/Redis) + 쓰기 시 evict — 프록시 진입점 규칙 준수 (`CLAUDE.md` 함정 목록)
- 실시간 반영 목표: 같은 매장 화면 간 1초 내 (WebSocket)

### 5.4 운영

- dev(H2·mock·시드) / prod(MySQL·Flyway V32+) 프로필 분리, docker compose 풀스택
- Sentry 에러 추적(모드 전환형), actuator health

## 9. 용어집

| 용어 | 의미 |
|---|---|
| 매장(Store) | 과금·권한·데이터의 기본 스코프 단위 |
| 시프트(Shift) | 스케줄 보드의 근무 1건. 야간이면 익일 종료 |
| 정산주기(PayrollCycle) | 매장별 급여 산정 기간+지급일 설정 |
| 확정(Confirm) | 스케줄/급여를 잠그고 알림을 발송하는 행위. 수정 시 리셋 |
| 게이팅(Gating) | `PlanFeature` 기반 서버측 기능 제한 |
| 개인 모드(Personal Mode) | 매장 소속 없이 혼자 근무를 기록하는 **상태**. 역할이 아니며 계정 등급을 바꾸지 않는다(§2.1) |
| 무소속 근로자 | 개인 모드의 대상 페르소나. "프리랜서"·"1인사업자" 표현은 근로자성 오인 우려로 쓰지 않는다 |
| 자기신고 기록 | 개인 모드의 출퇴근 기록. 제3자(사업주) 확인이 없어 매장 기록과 증명력이 다르다 |
