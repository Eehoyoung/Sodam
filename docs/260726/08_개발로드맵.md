# 08. 개발 로드맵

1차 범위는 PRD §4 전체([00_개요_및_요구사항정의서.md](00_개요_및_요구사항정의서.md) §5)로 확정됐지만, 엔지니어링상 한 번에 구현할 수 없으므로 Phase로 분할한다. 각 Phase는 이전 Phase의 산출물 위에 쌓인다.

## Phase 0 — 기초 인프라 (착수 전제 조건)

**추정 기간: 2주** (2~3인 팀 가정 — 실제 팀 규모 확정 후 재산정 필요, 이 추정치는 상대적 우선순위 파악용)

- Next.js 프로젝트 스캐폴드(App Router, TypeScript, Tailwind, shadcn/ui 초기 설정), 모노레포 내 `web-master/` 디렉터리로 생성([01_시스템아키텍처.md](01_시스템아키텍처.md) §5)
- 웹 전용 인증 배선: `POST /api/web/auth/login`, Spring Session Data Redis 도입(세션 전용 인스턴스 분리 + **Sentinel/Cluster HA를 이 단계에서부터 구성**), `SecurityFilterChain` 경로 분리([01_시스템아키텍처.md](01_시스템아키텍처.md) §4)
- **인증 principal에 사장/매니저 역할 정규화 포함** — 매니저도 동일 `/api/web/auth/login`으로 로그인하고, 세션에 담긴 `storeRole`/위임 권한에 따라 UI·API가 제한되도록 Phase 0에서 이미 지원한다([00_개요_및_요구사항정의서.md](00_개요_및_요구사항정의서.md) §4). 단 "매니저에게 권한을 부여하는" 위임 관리 화면 자체는 Phase 4
- CSRF 방어(Double Submit Cookie 자체구현), CSP 헤더, 로그인 rate limit·계정잠금(5회) 등 기본 보안 배선([04_보안정책.md](04_보안정책.md))
- 디자인 토큰 이식(v3 컬러/그라디언트) 및 기본 레이아웃(사이드바+상단바) 컴포넌트, 권한별 메뉴 노출 처리([03_UI_UX_설계가이드.md](03_UI_UX_설계가이드.md) §1)
- `docker-compose.yml`에 `sodam-web-master` 서비스 통합([07_배포_운영계획.md](07_배포_운영계획.md) §2)
- CI 파이프라인 구축(lint/typecheck/test/build)
- **완료 기준**: 사장·매니저 각각 웹에서 로그인해 빈 대시보드 셸을 볼 수 있고, 세션이 401/만료 규칙대로 동작하며, 매니저 세션은 권한 밖 메뉴가 렌더링되지 않는 것을 E2E로 검증

## Phase 1 — MVP (조회 중심)

**추정 기간: 3주**

- 매장 목록/상세 조회, 매장 전환
- 직원 목록/상세 조회
- 출퇴근 현황 대시보드(실시간 STOMP 연동 포함)
- 스케줄 조회(읽기 전용 보드)
- NFC 태그 목록 조회(비활성화는 Phase 2, [00_개요_및_요구사항정의서.md](00_개요_및_요구사항정의서.md) §5)
- 홈 대시보드 BFF 집계([02_API_활용계획.md](02_API_활용계획.md) §2) — **이 Phase 완료 시점에 BFF 응답시간(P95) 실측**, 목표(800ms) 초과 시 Spring 집계 엔드포인트 전환 여부 결정([02_API_활용계획.md](02_API_활용계획.md) §11
- **완료 기준**: 사장이 웹에서 매장 현황을 "보는" 모든 화면이 모바일과 데이터 정합성을 유지하며 동작, BFF 응답시간 실측 완료

## Phase 2 — 핵심 쓰기 기능

**추정 기간: 4주**

- 사장승인 출퇴근 승인/거절, 이상탐지 처리
- 스케줄 편성(드래그앤드롭 CRUD)
- NFC 태그 비활성화
- 직원 시급/월급 변경안 처리
- 연차/휴무 승인
- **낙관적 락 1차 적용**: 출퇴근·스케줄·매장(NFC 등) 계열 엔티티([06_DB_마이그레이션계획.md](06_DB_마이그레이션계획.md) V63/V64/V67)
- **완료 기준**: 동시 편집 시나리오(모바일↔웹) E2E 테스트 통과, 409 Conflict UX 검증

## Phase 3 — 급여 및 노무

**추정 기간: 4주**

- 급여 정산 마법사(3단계), PDF 발급
- 급여 정책 설정, 보너스 등록
- 멱등성 키·분산 락 적용([05_동시성제어_및_고급아키텍처.md](05_동시성제어_및_고급아키텍처.md) §3, §7)
- **낙관적 락 2차 적용**: 급여·직원계약 계열([06_DB_마이그레이션계획.md](06_DB_마이그레이션계획.md) V65/V66)
- 노무 안전장치 경고 노출(문구는 기존 그대로, 신규 문구 추가 금지)
- **완료 기준**: 급여 확정 중복 실행 방지가 실제 네트워크 재시도 시나리오에서 검증됨

**Phase 2를 Phase 3보다 먼저 두는 이유(확정, 순서 유지)**: 스케줄·출퇴근은 매일 반복되는 고빈도 작업이라 동시성 인프라(낙관적 락, 409 UX)를 상대적으로 리스크가 낮은 도메인에서 먼저 검증한 뒤, 금전이 직결되는 급여 도메인에 같은 인프라를 적용하는 편이 안전하다.

## Phase 4 — 확장 기능

**추정 기간: 5주**

- 매니저 위임 **관리**(권한 부여/회수 UI, 감사이력 — `accessChannel` 포함) — CONTRACT_MANAGE/PAYROLL_CONFIRM 제외 원칙 유지. (매니저 본인의 웹 *로그인/사용*은 이미 Phase 0부터 가능 — 이 Phase는 "권한을 부여하는" 사장 전용 관리 화면만 다룸)
- 구인채용(공고/지원자/인증매칭)
- 전자계약 발송/상태 추적
- **낙관적 락 3차 적용**: 구독·구인채용 계열([06_DB_마이그레이션계획.md](06_DB_마이그레이션계획.md) V68)
- 구독/결제 관리 화면 — **Toss Web SDK 연동은 계약 확인 전까지 착수 금지**([07_배포_운영계획.md](07_배포_운영계획.md) §6 TODO)
- **완료 기준**: PRD §4 전 항목이 웹에서 사장 기준으로 동등하게 접근 가능
