# 00. 사장님 웹 콘솔 — 프로젝트 개요 및 요구사항정의서

## 1. 배경

소담(Sodam)은 현재 React Native 모바일 앱으로만 서비스된다. 사장(Master)은 매장 등록부터 직원관리·출퇴근 승인·스케줄 확정·급여 정산·매니저 위임·구인채용까지 매장 운영 전 업무를 모바일 앱에서 처리한다. 그러나 다음과 같은 실사용 제약이 반복적으로 확인된다.

- 급여 정산·스케줄 편성처럼 여러 직원의 데이터를 한 화면에서 비교·편집해야 하는 작업이 모바일 화면 폭에서 비효율적이다.
- PC로 매장을 관리하는 사장(특히 5인 이상 사업장, 멀티매장 운영자)의 데스크톱 작업 수요가 있다.
- 노무 서류(근로계약서·급여명세서·PDF)는 출력·저장·이메일 첨부 등 데스크톱 워크플로우와 친화적이다.

이에 **사장 전용 데스크톱 웹 콘솔**을 신규 개발한다.

## 2. 목표

- 모바일 앱의 사장(Master) 역할 기능을 웹에서 동등하게(또는 데스크톱에 맞게 개선된 형태로) 제공한다.
- 모바일과 데이터·상태를 실시간 공유한다 (같은 백엔드, 같은 STOMP 토픽 사용).
- 향후 AI 기반 기능(급여 이상탐지 코멘트, 스케줄 자동추천, 노무 리스크 요약 등) 추가를 염두에 두고 유지보수하기 쉬운 스택으로 시작한다.

## 3. 비목표 (이번 프로젝트 범위 밖)

- **직원(Employee) 전용 웹 화면**은 만들지 않는다. 이 콘솔은 사장·매니저(위임 권한 보유자) 전용이다.
- 기존에 부분 구축된 `react-native-web` 기반 웹 빌드(`frontend/build:web*`)를 이 프로젝트의 기반으로 재사용하지 않는다 — 사유는 [01_시스템아키텍처.md](01_시스템아키텍처.md) §1.
- 모바일 전용 하드웨어 기능(NFC 태그 스캔, GPS 실시간 위치 기반 출퇴근 체크인 그 자체)은 웹에서 대체 구현하지 않는다. 웹은 **조회·승인·설정** 중심이며, 현장 출퇴근 체크인은 계속 모바일이 담당한다.
- 결제 수단 신규 도입(웹 전용 PG 등)은 다루지 않는다 — 기존 Toss 연동을 그대로 활용한다.

## 4. 대상 사용자

| 사용자 | 설명 | 우선순위 |
|---|---|---|
| 사장(Master) | 매장 소유자, 전 기능 접근 | 1순위 |
| 매니저(위임받은 Employee) | `EmployeeStoreRelation.storeRole` 기반 부분 권한 보유자 | **1차 범위 포함** — 웹 전용 로그인 API(`/api/web/auth/login`)를 매니저 계정도 그대로 사용하며, 로그인 이후 위임받은 권한 범위 내에서만 메뉴/API가 노출된다(§4.11 참고, `CONTRACT_MANAGE`/`PAYROLL_CONFIRM`은 노무사 게이트로 인해 웹에서도 제외). 단 "매니저 권한을 부여하는" 위임 관리 화면 자체는 사장 전용이며 [08_개발로드맵.md](08_개발로드맵.md) Phase 4에 위치 — Phase 0~3에서도 매니저는 이미 위임받은 범위 내 기능(예: 출퇴근 승인)을 웹에서 쓸 수 있어야 한다 |

## 5. 요구사항 — PRD §4 전체 기능의 웹 매핑

1차 개발 범위는 **PRD.md §4 전체(4.1~4.12)**로 확정됐다. 아래는 각 도메인이 웹 콘솔에서 어떻게 다뤄지는지의 요건 정의다. 상세 API는 [02_API_활용계획.md](02_API_활용계획.md), 화면 설계는 [03_UI_UX_설계가이드.md](03_UI_UX_설계가이드.md) 참고.

| PRD 섹션 | 기능 | 웹 요건 |
|---|---|---|
| 4.1 | 인증·온보딩 | 이메일/카카오/Apple 로그인 웹 플로우, 약관 동의는 유지하되 **위치정보 수집 동의는 웹 온보딩에서 제외**(웹은 GPS 체크인을 제공하지 않으므로 불필요 — 매장 등록 시 주소→좌표 지오코딩은 위치정보 "수집"이 아니라 입력 주소의 좌표 변환이라 별도 동의 불필요로 판단), 세션 기반 인증(모바일 JWT와 별도) |
| 4.2 | 매장 | 매장 등록(주소검색→지오코딩), 초대코드 발급/재발급, NFC 태그는 **목록조회·비활성화만 1차 범위**(물리 태그에 값을 쓰는 "발급"은 NFC 하드웨어가 필요해 모바일 전용으로 유지), 매장수 플랜게이팅 웹 표시 |
| 4.3 | 직원관리·계약 | 직원 목록/상세, 시급/월급 변경(DRAFT→SIGNING→VERIFIED→APPLIED 변경안 프로세스 그대로), 전자서명 계약 발송·상태 추적, 미성년 보호 규칙 노출 |
| 4.4 | 출퇴근 | 실시간 출퇴근 현황판(대시보드 핵심 화면), 사장승인 방식 요청 목록/승인·거절, 출퇴근 이상탐지·정정요청 처리 — **GPS/NFC 체크인 자체는 웹에서 제공 안 함** |
| 4.5 | 스케줄 | 드래그앤드롭 보드(데스크톱에서 더 유리한 UX), 템플릿, 확정 시 알림, 교대요청 승인, 연차/휴무 승인 |
| 4.6 | 급여 | 정산주기 설정, 4대보험/세금/퇴직금 계산, 정산마법사 3단계 + PDF 다운로드, 급여 RBAC(본인+사장만 열람) 그대로 적용 |
| 4.7 | 노무 안전장치 | 최저임금/52시간/휴게 경고 대시보드 노출, 근로감독 증거패키지(PREMIUM) 다운로드. **문구는 노무사 검토 전이므로 기존 문구 그대로 이식, 신규 문구 추가 금지** |
| 4.8 | 수익화 | 플랜 조회/변경/해지/일시정지 화면, 결제는 기존 Toss 연동 그대로(웹용 결제위젯 별도 검토), 게이팅은 서버(`PlanFeature`) 강제 원칙 유지 |
| 4.9 | 알림·실시간 | STOMP WebSocket 재사용, 웹은 브라우저 알림(Web Push) 검토 — FCM 앱 종료 푸시는 웹 특성상 해당 없음 |
| 4.10 | 부가 도메인 | 매출 통계, 홈/마이페이지/설정, Q&A, 관리자 시스템 화면 |
| 4.11 | 매니저 위임 | 권한 부여/회수, 위임 감사이력 조회. **CONTRACT_MANAGE/PAYROLL_CONFIRM 확장 금지** 원칙 유지 |
| 4.12 | 인증채용(구인) | 구인공고 게시/수정/마감, 지원자 목록, 인증매칭 결과 조회. PII 최소화 원칙 그대로 |

### 5.1 티어 게이팅 (PRD §4.8 요약, 웹에서도 동일 적용)

FREE(무료, 직원 2명, PDF 잠금) / STARTER(9,900원, 5명, +명세서 PDF·퇴직금·기본 노동법 경고) / PRO(19,900원, 무제한, +전체 노동법·연차·4대보험 신고서·전자계약·멀티매장) / PREMIUM(39,900원, 무제한, +전담 CS·세무노무 연결·증거패키지). **게이팅은 웹 BFF가 아니라 항상 기존 백엔드 `PlanFeature` 서버 검증에 위임한다** — 웹 프론트는 UX상 잠금 표시만 하고 신뢰 경계로 사용하지 않는다.

## 6. 성공 지표 (제안)

- 사장 1인당 데스크톱 세션에서 평균 작업 완료 시간(급여 정산, 스케줄 편성)이 모바일 대비 단축
- 웹 콘솔 도입 후 5인 이상 매장의 급여 정산 소요 시간 감소
- 웹·모바일 간 데이터 불일치(동시 편집 충돌) 발생률 0에 수렴 — [05_동시성제어_및_고급아키텍처.md](05_동시성제어_및_고급아키텍처.md) 참고

## 7. 확정 (2026-07-26, 2차 확인)

- 위치정보 수집 동의는 웹 온보딩에서 불필요 — 제외 확정
- 매니저 웹 접근 1차 범위 포함, 웹 전용 로그인 API 신설로 대응
- NFC 태그는 목록조회·비활성화만 1차 포함, 발급은 모바일 전용 유지

남은 확인 필요 항목은 없음 — 세부 구현 이슈는 각 하위 문서([01](01_시스템아키텍처.md)~[08](08_개발로드맵.md))의 확인 필요 섹션 참고.
