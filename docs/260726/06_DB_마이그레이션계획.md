# 06. DB 스키마 및 마이그레이션 계획

## 1. 원칙

- 웹 콘솔은 **기존 스키마를 그대로 재사용하는 것을 기본값**으로 한다. 웹이라는 이유로 별도 데이터 모델을 만들지 않는다(동일 매장·직원·급여 데이터를 두 클라이언트가 공유).
- 신규 컬럼/테이블이 필요한 경우에만 Flyway `V{n}__{설명}.sql`을 추가한다. 현재 최신 버전은 `V62__user_apple_sub.sql`이므로 **다음 버전은 V63부터** 시작한다.
- 기존 V파일은 절대 수정하지 않는다(체크섬 규칙, [api-design.md](../../.claude/rules/api-design.md) 준수).
- 아래 테이블명은 `backend/src/main/java/com/rich/sodam/domain/` 하위 `@Entity` 클래스를 실제로 확인해 도출했다(2026-07-26 조사, `@Table` 명시가 없는 엔티티는 Hibernate 기본 네이밍 전략에 따라 클래스명을 snake_case로 변환한 이름을 사용 — 코드에서 `payroll`/`payroll_detail`/`payroll_policy`/`refresh_token`/`work_shift`/`job_posting`/`time_off` 등 기존 V파일로 실측 확인됨).

## 2. 신규 스키마 변경

### 2.1 낙관적 락 `@Version` 컬럼 추가 ([05_동시성제어_및_고급아키텍처.md](05_동시성제어_및_고급아키텍처.md) §2)

**범위 확정**: append-only 로그·감사·토큰성 엔티티를 제외한 쓰기 가능 엔티티 전부(34종). 이미 `@Version`을 보유한 5종(`Store`/`EmployeeStoreRelation`/`EmploymentAmendment`/`ElectronicSignatureEnvelope`/`ElectronicSignatureParty`)은 제외.

### 2.2 감사로그 접근 채널 구분 ([04_보안정책.md](04_보안정책.md) §8)

```sql
-- V69__add_access_channel_to_store_delegation_audit.sql
ALTER TABLE store_delegation_audit ADD COLUMN access_channel VARCHAR(10) NOT NULL DEFAULT 'MOBILE';
```

`StoreDelegationAudit` 엔티티에 `accessChannel` 필드(enum 또는 문자열, `WEB`/`MOBILE`) 추가.

### 2.3 웹 세션은 DB가 아닌 Redis에 저장

Spring Session Data Redis를 사용하므로 **웹 세션 자체를 위한 신규 MySQL 테이블은 만들지 않는다** — Redis가 세션 스토어 역할을 전담한다([01_시스템아키텍처.md](01_시스템아키텍처.md) §4.2).

### 2.4 멱등성 키 저장 ([05_동시성제어_및_고급아키텍처.md](05_동시성제어_및_고급아키텍처.md) §3)

멱등성 키도 TTL이 있는 단기 데이터이므로 MySQL이 아닌 **Redis**에 저장한다(신규 테이블 불필요).

## 3. Redis 인프라 (참고 — 스키마 변경 아님)

- 세션 전용 Redis 인스턴스는 **초기 출시부터 Sentinel(또는 Cluster) 이중화 적용**을 전제로 한다([01_시스템아키텍처.md](01_시스템아키텍처.md) §4.2, [05_동시성제어_및_고급아키텍처.md](05_동시성제어_및_고급아키텍처.md) §4). 이는 DB 마이그레이션이 아니라 인프라 프로비저닝 항목이므로 [07_배포_운영계획.md](07_배포_운영계획.md)에서 다룬다.

## 4. dev/test 프로필 영향

- dev(H2, `ddl-auto: create-drop`)와 test는 엔티티에 `@Version` 필드를 추가하면 자동 반영되므로 별도 조치 불필요.
- prod(MySQL, `ddl-auto: validate` + Flyway)는 **엔티티 변경과 대응 V파일을 반드시 같은 커밋에 포함**해야 한다(CLAUDE.md 원칙).

## 5. 확인 필요

남은 확인 필요 항목 없음. 단, 구현 착수 시 위 34개 엔티티 목록이 실제 코드 변경 시점까지 늘거나 줄지 않았는지(신규 엔티티 추가/삭제) 재확인하는 것을 권장한다 — 이 문서는 2026-07-26 시점 스냅샷이다.
