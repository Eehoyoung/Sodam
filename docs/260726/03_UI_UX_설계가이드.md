# 03. UI/UX 설계 가이드

## 1. 레이아웃 원칙

모바일 앱은 단일 컬럼 스택형 화면이지만, 웹 콘솔은 데스크톱 SaaS 대시보드 표준 레이아웃을 따른다.

```
┌──────────────────────────────────────────────────┐
│ 상단바: 매장 전환 · 알림 · 프로필                    │
├───────────┬────────────────────────────────────────┤
│ 좌측       │                                        │
│ 사이드바   │            메인 콘텐츠 영역              │
│ (고정 240px)│    (대시보드 / 테이블 / 보드 / 폼)      │
│           │                                        │
│ - 홈       │                                        │
│ - 매장관리 │                                        │
│ - 직원관리 │                                        │
│ - 출퇴근   │                                        │
│ - 스케줄   │                                        │
│ - 급여     │                                        │
│ - 매니저   │                                        │
│ - 구인채용 │                                        │
│ - 설정     │                                        │
└───────────┴────────────────────────────────────────┘
```

- 사이드바는 모바일 앱의 하단 탭/드로어 내비게이션과 정보구조(IA)를 동일하게 유지해 사장이 두 플랫폼을 오가도 혼란이 없게 한다.
- 멀티매장 사장을 위해 상단바에 **매장 전환 드롭다운**을 상시 노출한다(모바일의 `StorePassRow` 개념을 웹 버전으로 이식).
- 매니저(위임 권한자) 로그인 시 사이드바는 위임받은 권한 범위 밖의 메뉴 항목을 아예 렌더링하지 않는다(숨김이 아니라 미노출 — 비활성화 표시로 권한 부족을 노출하지 않는다). 백엔드 인가(`StoreAccessGuard`)가 최종 신뢰 경계이며 UI 숨김은 UX 편의일 뿐이라는 원칙은 모바일과 동일.

## 2. 디자인 시스템 v3("링&패스") 웹 확장

`frontend/theme/tokens.ts`의 v3 컬러 토큰(코랄 `#FF4D6D` → 틸 `#12B8A6` 그라디언트, `colors`/`darkColors`/`gradient`)을 웹에서도 동일한 브랜드 아이덴티티로 재사용한다.

| 모바일 v3 컴포넌트 | 웹 대응 컴포넌트 | 비고 |
|---|---|---|
| `ProgressRing`(출퇴근 진행률) | 대시보드 상단 KPI 카드의 도넛 차트로 확장 | 데스크톱은 여러 명의 진행률을 그리드로 동시 표시 |
| `StorePassRow`(매장 전환) | 상단바 드롭다운 | §1 참고 |
| `QuickMenuGrid` | 홈 대시보드의 바로가기 카드 그리드 | 데스크톱은 더 많은 항목을 한 화면에 노출 가능 |
| `AppCard` (`spot`/`plain`/`warm` variant) | Tailwind 컴포넌트로 토큰만 이식(구현은 shadcn/ui 기반 신규) | 컬러 토큰 값은 그대로, 컴포넌트 구현체는 웹 스택에 맞게 새로 작성 |

토큰 값 자체(HEX, 그라디언트 각도 등)는 `frontend/src/theme/tokens.ts`를 **단일 진실 공급원(SSOT)**으로 삼아 웹 프로젝트에도 동일 값을 복제한다. 두 프로젝트가 물리적으로 분리되어 있으므로(§[01_시스템아키텍처.md](01_시스템아키텍처.md) §1), 토큰 값 변경 시 양쪽을 함께 갱신해야 한다는 점을 개발 체크리스트에 명시한다.

## 3. 반응형 정책

- **데스크톱 우선**(최소 지원 너비 1280px). 웹 콘솔은 태블릿(768px~1279px)에서 사이드바를 축소 아이콘형으로 전환하는 정도까지만 대응한다.
- **모바일 폭(< 768px) 전용 최적화는 하지 않는다** — 모바일에서는 기존 앱 사용을 유도하는 안내 배너만 표시한다(중복 구현 방지, [00_개요_및_요구사항정의서.md](00_개요_및_요구사항정의서.md) 비목표 참고).
- 다크모드는 모바일 앱과 동일하게 `prefers-color-scheme` 기반 자동 대응 + 수동 토글을 제공한다.

## 4. 주요 화면 정의

| 화면 | 핵심 요소 |
|---|---|
| 홈 대시보드 | 오늘 출퇴근 KPI 링, 승인 대기 알림 카드, 이번달 매출/인건비 요약, 최근 알림 피드 |
| 매장 관리 | 매장 목록(멀티매장 그리드), 매장 상세 탭(기본정보/운영시간/NFC태그/사진) |
| 직원 관리 | 테이블 뷰(이름/역할/시급/계약상태/최근출근), 상세는 **별도 페이지로 전환**(`/employees/{id}`)해 편집 — 사이드시트가 아닌 전체 페이지 방식으로 확정(§6) |
| 출퇴근 현황 | 실시간 테이블(재직중/지각/결근 필터), 사장승인 요청 큐, 이상탐지 배지 |
| 스케줄 보드 | 주간 캘린더 드래그앤드롭(요일×직원 그리드), 템플릿 사이드 패널 |
| 급여 정산 마법사 | 3단계 스텝퍼(대상선정→계산확인→발급), 각 단계 요약 사이드바, PDF 미리보기 |
| 매니저 위임 | 직원별 권한 매트릭스(체크박스 그리드), 감사이력 타임라인 |
| 구인채용 | 공고 목록/에디터, 지원자 칸반(검토중/제안/확정) |
| 설정 | 플랜/결제, 계정, 알림 설정 |

## 5. 접근성

- WCAG 2.1 AA 기준을 목표로 한다: 명도 대비 4.5:1 이상, 모든 인터랙션 요소 키보드 접근 가능, 폼 필드 `label` 연결.
- 급여·계약 등 법적 효력이 있는 문서 다운로드/서명 액션은 스크린리더로도 명확히 인지 가능하도록 `aria-label` 필수 부여.
- 색상만으로 상태를 구분하지 않는다(예: 출퇴근 이상탐지는 색상+아이콘+텍스트 라벨 동시 사용) — 모바일 앱에서 이미 확립된 원칙을 웹에도 적용.

## 6. 확정 (2026-07-26, 2차 확인)

- 직원/매장 상세 편집은 **페이지 전환 방식**으로 확정(사이드시트 채택 안 함)
- 다국어 지원은 **1차 한국어 전용** — 영어 등 다국어는 이번 범위에 포함하지 않는다
