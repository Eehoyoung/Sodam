## ⚠️ 0. 시작 전 반드시 처리 (병렬 실행이 깨진다)

### 신규 문서는 `.gitignore`에 걸린다

`.gitignore` 현재 상태:
```
docs/
**/docs/
*.png
*.html
*.md
!/README.md
```

**기존 `docs/` 17개 파일은 규칙 추가 전부터 추적 중이라 살아 있다.**
(`docs/PRD.md`, `docs/RELEASE_GATES.md`, `AGENTS.md` 전부 tracked — 확인 완료)

**그러나 새로 만드는 `docs/260815/*.md`는 자동으로 추적되지 않는다.**
그리고 `.worktreeinclude`는 `.env` 계열만 복사한다:
```
.env
backend/.env
frontend/.env
frontend/android/local.properties
```

→ **병렬 worktree를 만들면 계획서와 goal.json이 그 worktree에 없다.**
→ G2 병렬 작업 에이전트가 사양을 못 읽는다.

**조치 (작업 시작 전 1회)**
```powershell
git add -f docs/260815/260815_소담_포지셔닝전환_계획서.md
git add -f docs/260815/260815_소담_포지셔닝전환_goal.json
git add -f docs/260815/260815_소담_코드작업_지침.md
git commit -m "docs: 포지셔닝 전환 계획서·작업지시·코드지침 추가"
```
**이걸 안 하면 병렬 실행이 조용히 실패한다.** 에이전트가 사양 없이 추측으로 짠다.

## 3. DB — Flyway (여기서 사고가 가장 많이 난다)

| 규칙 | 내용 |
|---|---|
| 신규 파일 | `V92__설명.sql` 부터 (현재 최신 `V91`) |
| **기존 V파일 수정** | **절대 금지.** 체크섬이 깨져 다른 환경에서 검증 실패 |
| 엔티티 변경 시 | 대응 마이그레이션을 **같은 커밋에** 작성 |
| 검증 | `spring.jpa.hibernate.ddl-auto=validate`가 부팅 시 불일치를 즉시 잡는다 |
| 로컬 초기화 | `docker compose down -v` → **로컬 개발 데이터 전부 소실**. 함부로 실행 금지 |

**Hibernate가 알아서 컬럼을 추가해주지 않는다.** 엔티티만 바꾸고 마이그레이션을 빼먹으면
부팅이 실패한다.

**이번 작업에서는 신규 테이블을 만들지 않는 것이 원칙이다(HC-12).**
`LaborRiskService`는 기존 데이터만 재사용하도록 설계돼 있다. 그 철학을 유지한다.

## 4. API 계약 — 어기면 앱이 조용히 죽는다

### 상태 코드 (과거 사고 이력 있음)

| 상황 | 반환 | 이유 |
|---|---|---|
| **만료된 JWT** | **401** | 403을 주면 FE의 리프레시 루프가 죽는다 (커밋 `322e9a0`) |
| **플랜 상한 초과** | **402 + `errorCode`** | FE가 이 코드로 페이월 화면을 분기한다 (커밋 `76176c0`) |
| 권한 없음 | 403 | |

### 인가 — 신규 엔드포인트 전부 적용

```java
@MasterOnly
// + StoreAuthorizationPolicy.assertMasterOwnsStore(...)
```

- 리스크·상시근로자·대시보드 API는 **전부 사장 전용**이다.
- 직원 계정으로 접근 시 403을 반환하는 테스트를 반드시 남긴다.
- **플랜 게이팅은 서버에서 검증한다.** 클라이언트가 보낸 플랜 값을 절대 신뢰하지 않는다.

## 9. 작업 방식

### 대규모 배선 파악은 Graphify

호출 관계·영향 범위 추적이 필요하면 추측하지 말고 도구를 쓴다.
```
graphify query    / explain    / path    / affected
```
특히 `LaborRiskService`에 RiskType을 추가할 때 **소비처를 `affected`로 먼저 확인**한다.
(`.graphifyignore` 존재)

### 작업 지시 가공

코드 작성·수정·조사·버그 수정·리팩토링·설계 검토는 **메인 작업 전에 지시를 먼저 정리**한다:
목표 / 대상 파일·영역 / 세부 작업 / 관련 프로젝트 규칙 / 확인 필요 사항.
단순 설명 요청이나 짧은 후속 지시에는 적용하지 않는다.

### 커밋 단위

- 엔티티 변경 + Flyway 마이그레이션은 **같은 커밋**
- WP 하나 = 커밋 하나를 권장
- 코드 주석에는 **게이트 ID만** 적는다. 설명을 복제하면 반드시 어긋난다
  ```java
  // G-18: 상시근로자 산정 기준 노무사 회신 대기
  ```
